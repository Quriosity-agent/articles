# Yann Dubois 访谈拆解：AI 进展突然变“真实”，不是因为智能跃迁，而是可靠性过线

> Source: [The MAD Podcast with Matt Turck — OpenAI’s Yann Dubois on Why AI Progress Suddenly Feels Real](https://www.youtube.com/watch?v=DhD1zZ8w8Mw&t=2s)  
> Published: 2026-05-21  
> Tags: OpenAI / Yann Dubois / GPT-5.5 / Post-training / RL / Evals / Agent Harness / Continual Learning

AI 这几个月为什么突然让人觉得“真的能干活了”？

OpenAI 的 Yann Dubois 在 The MAD Podcast 里给出的答案，不是“某一天模型突然开悟”，而是一个更工程化、也更重要的解释：**能力曲线可能一直是连续的，但可靠性跨过阈值以后，用户行为会突然改变。**

一个模型从 70 分到 80 分，可能只是让人觉得 demo 更惊艳；但从 90 分到 95 分，可能意味着用户终于愿意把真实任务交给它。体感上的“阶跃”，不一定来自智能本身断崖式跃迁，而是来自可用性阈值被跨过。

这也是这期访谈最值得拆解的地方。它把当下 AI 竞争从“模型有多聪明”重新拉回到几个更具体的问题：可靠性、后训练、强化学习、评估、agent harness、企业记忆，以及 startup 的最后一公里。

## 一、真正的分水岭不是能力展示，而是可靠性

Yann 对可靠性的解释很接近 agent 工程里的直觉：如果一个 agent 每隔几分钟都有概率犯错，那么任务越长，最后失败的概率越高。

短 demo 可以靠运气撑过去。长任务不行。

这意味着 AI agent 的可用性不是单步准确率的线性函数，而更像一个乘法问题：

- 每一步 95% 可靠，跑 20 步以后整体成功率会明显下降；
- 每一步 99% 可靠，长任务才开始有商业意义；
- 如果中间还涉及工具调用、文件修改、权限、外部 API、用户意图理解，错误会继续累积。

所以“突然变真实”的关键不是模型第一次能写代码、能用浏览器、能总结资料。这些能力早就出现了。关键是：**它开始足够少犯低级错，用户才敢把真实 workflow 交给它。**

这也解释了为什么 coding 最先让人感到跃迁。代码任务天然带有反馈回路：测试能跑，类型能查，diff 能审，CI 能挡住一部分错误。相比法律、金融、咨询、战略研究这类开放任务，coding 更容易把可靠性推进到可用阈值。

## 二、GPT-5.5 的意义：不是单点能力，而是横向整合

Yann 提到 GPT-5.5 在 OpenAI 内部曾有代号 Spud，公司对这个发布高度兴奋。外部用户看到的可能是“更强的模型”，但从他的描述看，GPT-5.5 的核心更像一次多维能力整合。

它在几个方向尤其强：

1. **agentic coding**：不只是补全代码，而是能持续修改、调试、检查、推进任务；
2. **computer use**：能操作电脑和工具，而不是只在聊天框里回答；
3. **knowledge work**：能处理开放的资料搜集、分析和产出；
4. **早期科学研究**：能参与更长、更不确定的研究流程。

Yann 所在的 Post-Training Frontiers team 不是只优化某一个 vertical，而是把不同 vertical team 做出的能力整合起来，再优化横向能力：instruction following、function calling、memory、thinking time 分配等。

这件事很关键。因为真实世界任务失败，往往不是因为模型“不会那门知识”，而是因为横向行为不稳：

- 用户的指令理解错了；
- 工具调用参数错了；
- 该查资料时没查；
- 该停下来问澄清时硬猜；
- 该花时间思考时草率回答；
- 该快速执行时又过度推理。

模型产品真正进入工作流，靠的不是一个 benchmark 上的峰值分数，而是这些横向行为能不能被打磨到足够稳定。

## 三、Reasoning 的下一阶段：从“可验证题”走向“混乱工作”

O1/O1 Preview 的突破在于 test-time compute：模型可以想更久，而且想得越久，正确概率越高。

但早期 reasoning model 最容易优化的，是数学题和编程竞赛题。原因很简单：答案可验证。数学题有标准答案，代码题可以跑测试，强化学习有清晰 reward。

Yann 认为现在的变化，是类似的强化学习方法正在向更混乱的真实世界任务迁移：真实编程、知识工作、电脑使用、agent workflow。

这一步比做竞赛题难得多，因为真实任务通常有几个特点：

- 目标不完全明确；
- 信息不一定都在 prompt 里；
- 需要主动查资料；
- 中途需要发现缺失上下文；
- 成功标准不唯一；
- 很多失败直到最后才暴露。

也就是说，真正的难点不是让模型“想更久”，而是让它知道：什么时候该想，想什么，什么时候该行动，什么时候该回退，什么时候该质疑任务定义。

## 四、效率是另一条主线：把延迟—性能曲线往左推

访谈里一个容易被忽略但很重要的点，是 GPT-5.5 的效率。

Yann 说很多任务大约快了 2 倍。这个快，不只是推理工程把 token 生成得更快，也包括模型更会分配 thinking time。

可以把 reasoning 模型想象成一条曲线：

- x 轴是延迟或思考 token；
- y 轴是任务表现；
- 普通模式追求在合理延迟内给出足够好答案；
- Pro 模式沿着曲线继续往右走，用更多时间换更高正确率；
- 研究和工程的目标，是把整条曲线向左推。

这解释了 GPT-5.5 Thinking 和 GPT-5.5 Pro 的差别。Pro 不是“另一种智能”，而是投入更多 test-time compute。但增益会递减，曲线会 plateau。

更高效的模型像专家：不是把所有可能路径都试一遍，而是更早判断哪些路径值得走，哪些路径应该放弃。模型如果能学会更早 backtrack，就能用更少 token 得到同样质量。

这对产品很重要。用户不关心模型内部用了多少技巧，只关心：**等多久，花多少钱，结果靠不靠谱。**

## 五、Pretraining 没撞墙，但它不是全部

Yann 没法谈 OpenAI 内部 pretraining 细节，但他明确表示：pretraining 仍在持续产生收益。

这和过去两年的某些直觉不同。很多人曾以为互联网文本快被吃完，pretraining 会撞墙。但从 Yann 的说法看，更大的模型仍然可以带来两类收益：

1. **能力收益**：模型知道更多、抽象更强；
2. **效率收益**：模型可以在权重中“隐式思考”，减少显式 reasoning token。

第二点尤其有意思。大模型不一定意味着端到端延迟更差，因为更强的权重可能减少外显思考步骤，而且推理工程可以更好地并行化 GPU 计算。

这说明“模型越大越慢”不是绝对规律。真正要看的是完整系统：模型大小、生成 token 数、推理架构、并行效率、任务所需思考深度。

但 pretraining 只是让模型拥有一座巨大图书馆。它还不是一个好同事。

## 六、Mid-training：被低估的高质量数据加权阶段

Yann 对 mid-training 的定义很清楚：它位于 pretraining 和 post-training 之间，用更高质量、更接近最终目标的数据继续训练。

Pretraining 从整个互联网学习，里面既有 Wikipedia、GitHub、论文，也有广告、垃圾论坛、重复内容和噪声文本。Mid-training 的作用，是让模型在更高信号的数据上继续靠近目标能力。

这一步在公开讨论里没有 post-training、RL 那么耀眼，但它很可能是模型能力“顺手感”的关键来源之一。

因为很多能力不是靠最后阶段修出来的。最后阶段可以教模型如何回答、如何遵守指令、如何调用工具，但如果模型在更早阶段没有足够吸收高质量代码、知识结构、推理模式、专业语料，后训练会很吃力。

换句话说，mid-training 是把模型从“互联网平均水平”往“高质量工作语料”方向拉。

## 七、Post-training：把“知道很多”变成“对人有用”

Yann 的比喻很好：pretraining 像拥有一座巨大图书馆，post-training 像把图书馆变成一个能对话的专家。

Post-training 通常包括几类方法：

- **SFT**：人类给理想答案，模型学习模仿；
- **可验证奖励 RL**：数学、代码测试等任务可以明确判断对错；
- **偏好或部分可验证 RL**：通过 pairwise comparison、model-as-judge、用户效用信号等方式优化。

SFT 很有用，但有天花板。它本质上是行为克隆，模型学的是“人类示范长什么样”。如果人类示范不够好，模型很难超越示范。

RL 的意义在于，它优化 reward signal，而不是只模仿 gold answer。只要 reward 管道设计得足够好，模型可以通过采样、比较、强化，学到比示范更强的策略。

但 RL 不能太早开始。如果 base model 太弱，它很难“碰巧采样到好答案”，训练效率会很低。所以更合理的路线是：先用 pretraining、mid-training、SFT 把模型带到一个不错的位置，再用 RL 扩展能力边界。

## 八、为什么 RL 现在开始真正奏效

很多研究者曾经觉得 RL 太脆弱。Yann 也承认，他早期看到 ChatGPT 用 RL 时，第一反应是也许 SFT 就够了。Stanford Alpaca 某种意义上就来自这种判断。

现在他的看法变了：当 base model 已经足够强，拥有好的 world priors，RL 就开始变得有效。

这对机器人和 embodied AI 也有启发。过去机器人 RL 很难，是因为系统对世界理解太弱、探索成本太高、环境太复杂。但如果底层模型已经有足够常识和世界先验，RL 可能会稳定得多。

不过 RL 仍然有两个硬问题：

1. **采样成本高**：需要生成大量候选答案或 rollout；
2. **奖励归因稀疏**：长 agent 任务往往最后才知道成功失败，很难判断哪一步导致结果。

开源世界的 GRPO 之所以受欢迎，正是因为它简单、可规模化：采样多个答案，强化更好的答案。机器学习史上，经常是简单但能扩大规模的方法赢。

## 九、模型的 jaggedness：真正单位不是 domain，而是 skill class

为什么模型在某些任务上像专家，在另一些任务上像新手？Yann 的解释是：模型能力的单位未必是 domain，而更像 skill class。

数学竞赛和编程竞赛表面上是不同领域，但它们共享某些能力：符号推理、分步验证、搜索、约束满足、错误检查。模型在一个 skill class 上被强化后，可能迁移到相近任务。

反过来，两个同属“知识工作”的任务，也可能因为底层技能结构不同而迁移很差。咨询、金融、法律、医疗看起来都需要专业知识，但它们的真实难点包括：资料权限、事实核查、模糊目标、专业判断、责任边界、合规要求。

这就是为什么 benchmark intelligence 不会自动变成每个行业里的生产力。

一个 vertical 能多快进步，往往取决于三个条件：

- 有无高质量数据；
- reward 或评价是否可构造；
- 是否有真正懂这个 vertical 的人在持续盯模型行为。

Coding 进展快，不只是因为代码在网上多，而是因为模型开发者自己天天用，反馈回路密集，正确性也更容易验证。

## 十、幻觉问题：SFT 可能让模型学会“装知道”

Yann 引用了 John Schulman 的观点：SFT 可能鼓励幻觉。

原因是行为克隆会模仿答案形式。如果人类 gold answer 引用了一篇论文，而模型其实不知道那篇论文，SFT 可能教会它在类似场景里也生成看似专业的引用。

RL 在理论上更有机会减少这个问题。因为如果 reward pipeline 会惩罚 unsupported claims，模型采样出来的假引用、假事实、无根据推断就不会被强化。

这说明幻觉不只是“模型不知道”的问题，也是训练目标的问题。

如果训练目标奖励的是“像专家一样回答”，模型会学会专家腔。如果训练目标奖励的是“可支持、可验证、知道边界”，模型才会学会承认不知道、查证、引用来源。

这对产品也有直接启发：企业 AI 系统不要只优化回答流畅度，而要把 evidence、citation、tool trace、权限边界、拒答策略一起纳入评价。

## 十一、Evals 正在变成最难的部分

Yann 认为 eval 越来越难，原因有两个。

第一，任务更开放了。

以前可以评估“找出这个 bug”，因为 bug 是预先标注的。现在如果任务是“做一个实现 X 的网站”，好答案可能有很多种。设计、架构、交互、性能、可维护性都能影响评价，但很难有唯一标准答案。

第二，模型在某些轴上已经超过多数人类评审。

如果模型写出的代码、证明、设计、研究计划超过普通评审水平，谁来判断它到底好不好？这会把 eval 推向更专业、更昂贵、更动态的方向。

Model-as-judge 因此变得重要。更强模型可以成为更好的老师和评估者，形成 capability flywheel：模型帮助训练数据、帮助评价、帮助发现错误，再反过来提升模型。

但这里也有悖论：一旦你能构造一个好 eval，你往往也能把类似方法变成训练数据。于是 eval 很快过时。真正难的是持续构造不被训练集吞掉、又能代表真实用户效用的评价。

## 十二、Continual learning：为什么这件事还没解决，反而最意外

访谈后半段，Yann 特别提到 continual learning。他的图像很直观：

- x 轴是时间；
- y 轴是用户效用；
- 新模型第 0 天进入公司，可能已经比很多新人有用；
- 但人类新员工会随着时间学习公司上下文；
- 当前模型的效用曲线却相对平，因为它没有真正持续学习。

这可能是企业 AI 的下一条主线。

现在的 memory 和 personalization 还很早期。个人场景已经不够成熟，企业场景更复杂：权限、隐私、部门边界、知识更新、错误记忆、审计、遗忘权，都会变成系统问题。

但如果解决了，AI 的价值会从“一个聪明外包”变成“一个越来越懂公司的长期同事”。

这对所有 agent 产品都很关键。没有 continual learning，agent 每次都像临时工；有了可控的 continual learning，agent 才像组织的一部分。

## 十三、Harness 不会消失，但会不断重调

Matt 问了一个很实际的问题：今天外部 agent harness 做的事情，未来会不会被模型本体吃掉？

Yann 的回答很平衡：harness 今天非常有价值，尤其是在具体 vertical 里把可靠性从 80% 推到 85%、90%。但他不押注一个通用 harness 能长期不变，因为模型变化太快。

这点对创业公司很重要。

不要把 harness 理解成一个固定外壳。它更像一套随模型能力变化不断重调的工作流系统，包括：

- 工具选择；
- 权限控制；
- 上下文注入；
- 任务分解；
- 中间状态记录；
- 回滚和验证；
- 人类介入点；
- 评价和再训练数据收集。

如果模型能力冻结，单靠优秀 harness 就能释放很多价值。即使模型继续变强，harness 也不会马上消失，只是边界会变化：一部分策略被模型内化，另一部分会转向权限、集成、审计、组织流程。

## 十四、为什么 startup 仍然有空间

这期访谈最后给创业者的信号很明确：应用仍然值得做。

原因是瓶颈通常不是 raw intelligence，而是 last mile：

- 权限；
- connectors；
- 数据访问；
- 工作流集成；
- domain-specific product design；
- 某个 vertical 里的可靠性；
- 让用户真的敢把工作交出去的体验设计。

OpenAI 这样的模型公司会继续推进横向能力，但每个行业的最后一公里太细、太脏、太具体，不可能完全由通用模型层一次性解决。

这也是最值得创业公司切入的地方：不是再做一个聊天框，而是找到一个具体工作流，把模型、数据、权限、工具、评价、人类协作接成闭环。

## 结语：AI 的下一阶段，是把“聪明”变成“可托付”

这期访谈最重要的启发是：AI 进展的主线正在从“能不能做出来”转向“能不能托付”。

过去几年，模型证明了自己可以写代码、做题、聊天、总结、画图、调用工具。接下来真正的竞争是：

- 能不能长时间不偏航；
- 能不能知道自己什么时候不确定；
- 能不能把思考时间花在该花的地方；
- 能不能在真实组织里持续学习；
- 能不能被评估、审计、回滚和改进；
- 能不能通过 harness 和产品设计进入具体工作流。

所以“AI 突然变真实”并不是一个神秘事件。它更像很多连续改进叠到一起后，终于跨过了用户心理和业务流程里的可靠性阈值。

对模型公司来说，下一步是更强、更稳、更会学习的基础模型。对创业公司来说，机会在最后一公里：把这些模型放进真实工作，把 90% 可靠性打磨到用户敢用的 99%。
