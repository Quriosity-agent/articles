## TL;DR

Anthropic built a GAN-inspired "generator + evaluator" multi-agent architecture that breaks through single-agent ceilings in both frontend design quality and long-running autonomous coding. A one-sentence prompt can now produce a feature-complete full-stack application.

## The Problem: Why Single Agents Hit Walls

Anthropic's previous [long-running harness](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) used an initializer agent to decompose tasks and a coding agent to implement features one at a time. The community converged on similar patterns ("Ralph Wiggum" method, hooks-based iteration loops). But two fundamental issues persisted:

### 1. Context Anxiety

As the context window fills, models start wrapping up prematurely—they "think" they're running out of space. Sonnet 4.5 exhibited this so strongly that compaction (summarizing earlier context in place) wasn't enough. Full context resets were required: clear everything, hand off structured state to a fresh agent.

### 2. Self-Evaluation Bias

When asked to judge their own work, agents confidently praise mediocre output. This is especially bad for subjective tasks like design—there's no binary pass/fail equivalent. Even on verifiable tasks, agents exhibit poor judgment during execution.

**The key insight: separating the agent doing the work from the agent judging it is far more tractable than making a generator critical of itself.**

## Frontend Design: Making "Is This Good?" Gradable

Claude's default frontend output is technically functional but visually bland—safe layouts, predictable choices, zero aesthetic risk.

### Four Grading Criteria

Both the generator and evaluator received these criteria:

| Criterion | Description | Weight |
|-----------|-------------|--------|
| **Design quality** | Coherent whole vs. collection of parts? Distinct mood and identity? | **High** |
| **Originality** | Custom decisions or template defaults + "AI slop"? | **High** |
| **Craft** | Typography hierarchy, spacing, color harmony | Low (good by default) |
| **Functionality** | Can users understand and complete tasks? | Low (good by default) |

The criteria explicitly penalized "purple gradients over white cards" and other telltale AI-generation patterns.

### The Iteration Loop

- Built on the [Claude Agent SDK](https://platform.claude.com/docs/en/agent-sdk/overview)
- Generator creates HTML/CSS/JS frontends
- Evaluator uses **Playwright MCP** to navigate the live page (not static screenshots), scores each criterion, writes detailed critique
- Feedback loops back to generator for next iteration
- 5-15 iterations per generation, runs up to 4 hours

### The Creative Leap

A Dutch art museum website: iterations 1-9 produced increasingly polished dark-themed landing pages. Iteration 10 **scrapped everything** and reimagined the site as a 3D spatial experience—CSS perspective-rendered checkered floors, artwork hung in free-form positions on walls, doorway-based navigation between gallery rooms. This kind of creative leap had never appeared in single-pass generation.

## Full-Stack Coding: The Three-Agent Architecture

The GAN pattern scales naturally to software development, where code review and QA serve the same structural role as the design evaluator.

```
User: 1-4 sentence prompt
       ↓
   [Planner Agent]
   Expands prompt into full product spec
   Injects AI feature opportunities
       ↓
   [Generator Agent]
   Implements features in sprints
   React + Vite + FastAPI + SQLite
   Self-evaluates after each sprint
       ↓
   [Evaluator Agent]
   Uses Playwright MCP to click through the running app
   Grades against criteria with hard thresholds
   Fails sprints that don't meet the bar
```

### Sprint Contracts

Before each sprint, Generator and Evaluator **negotiate what "done" looks like**—Sprint 3's level editor contract had 27 test criteria. This bridges the gap between high-level spec and testable implementation.

### Head-to-Head: 2D Retro Game Maker

| Approach | Duration | Cost | Result |
|----------|----------|------|--------|
| Solo Agent | 20 min | $9 | Wasted space, core gameplay broken |
| Full Harness | 6 hr | $200 | 16 features, playable game, AI integration |

The solo version's game **simply didn't work**—entities appeared but didn't respond to input. The harness version had minor physics glitches but was playable with a complete feature set.

### Real Bugs the Evaluator Caught

| Contract Criterion | Evaluator Finding |
|--------------------|-------------------|
| Rectangle fill tool fills area with selected tile | FAIL — Only places tiles at drag start/end, doesn't fill region |
| User can delete entity spawn points | FAIL — Delete handler requires both `selection` and `selectedEntityId`, but clicking only sets one |
| Reorder animation frames via API | FAIL — PUT `/frames/reorder` route placed after `/{frame_id}`, FastAPI matches "reorder" as integer → 422 |

**Key lesson: Claude is a bad QA agent out of the box.** It identifies real issues then talks itself into approving them anyway. Multiple prompt tuning rounds were needed before the evaluator graded reasonably.

## Simplifying with Opus 4.6

### The Principle

> Every component in a harness encodes an assumption about what the model can't do on its own. Those assumptions are worth stress testing—they may be incorrect, or they can go stale as models improve.

### What Opus 4.6 Changed

- **Removed sprint decomposition** — Opus 4.6 can code coherently for 2+ hours straight
- **Removed context resets** — No more context anxiety
- **Evaluator becomes conditional** — Worth the cost only when tasks sit beyond what the model does reliably solo

### DAW (Digital Audio Workstation) Results

One-sentence prompt → 4 hours → $124 → Functional browser-based music production app

| Phase | Duration | Cost |
|-------|----------|------|
| Planner | 4.7 min | $0.46 |
| Build Round 1 | 2h 7min | $71.08 |
| QA Round 1 | 8.8 min | $3.24 |
| Build Round 2 | 1h 2min | $36.89 |
| QA Round 2 | 6.8 min | $3.09 |
| Build Round 3 | 10.9 min | $5.88 |
| QA Round 3 | 9.6 min | $4.06 |
| **Total** | **3h 50min** | **$124.70** |

The QA agent still caught critical gaps: "Clips can't be dragged on the timeline, no synth knobs or drum pads UI, no graphical EQ curves—these aren't edge cases, they're core DAW interactions."

## Practical Takeaways for Builders

### 1. Separate Generation from Evaluation

Don't let agents self-evaluate. Use an independent evaluator agent with concrete scoring criteria. Tuning an external evaluator to be skeptical is far more tractable than making a generator critical of its own work.

### 2. Re-examine Your Harness with Every Model Release

> "The space of interesting harness combinations doesn't shrink as models improve. Instead, it moves."

Opus 4.5 needed sprint decomposition + context resets. Opus 4.6 needs neither. Which components in your harness are still load-bearing?

### 3. Turn Subjective Judgment into Gradable Criteria

"Is this design good?" is hard to answer consistently. "Does this follow our design principles?" is gradable. This pattern applies to any subjective quality assessment.

### 4. Evaluators Should Interact, Not Just Observe

Use Playwright MCP to let the evaluator actually click through, navigate, and test the running application—like a real user would. Interactive evaluation catches far more than static assessment.

### 5. File-Based Agent Communication

Anthropic's approach is refreshingly simple—agents communicate by reading and writing files. One writes, another reads and responds within the same file or a new one. Simple, traceable, debuggable.

## The Bottom Line

This is Anthropic's most detailed practical account of harness engineering to date. The core messages:

- Single agents have ceilings; multi-agent architectures break through them
- GAN-style "generate + evaluate" loops are a general-purpose pattern
- Every model upgrade warrants re-simplifying your harness
- The real engineering value is in finding the next interesting harness combination

If you're building long-running agent coding tasks, the patterns in this post are worth stealing directly.
