# seedance2-skill 深度拆解：视频 Prompt 正在从“写词”变成 Agent 可执行的导演操作系统

[`donghaozhang/seedance2-skill`](https://github.com/donghaozhang/seedance2-skill) 是一个很小的 GitHub 仓库：它 fork 自 [`dexhunter/seedance2-skill`](https://github.com/dexhunter/seedance2-skill)，MIT 许可证，核心文件就是英文 `SKILL.md`、中文 `zh/SKILL.md`、中英文 README。README 里说得很直接：这是给 Claude Code、Cursor、Cline 等兼容 Agent 使用的 **Agent Skill**，目标是帮助用户为字节跳动即梦 Seedance 2.0 写更有效的视频生成提示词。

表面上看，它只是把 Seedance 2.0 的提示词经验整理成文档。但我觉得它真正值得看的一点是：**它把“会写视频 Prompt”这件事，从个人经验变成了 Agent 可调用、可安装、可复制的操作规范。**

这和最近我们一直在看的 AI 视频工具、QCut、短剧生产平台是同一条线：当视频生成模型越来越强，真正缺的不是又一个 prompt 片段，而是让创作者和 Agent 都能稳定使用模型能力的工作流层。

## 一句话概括

**seedance2-skill 的价值不是收集了一堆好词，而是把 Seedance 2.0 的输入限制、`@` 引用语法、运镜语言、分时段结构、场景模板和失败注意事项，包装成一个 Agent 可以读懂并执行的导演手册。**

这意味着视频 Prompt 不再只是“人类写给模型的一段文字”，而开始变成三层结构：

1. **平台约束层**：支持哪些输入、文件数量限制、时长限制、素材合规限制；
2. **导演语言层**：镜头、动作、节奏、转场、声音、风格如何组织；
3. **Agent Skill 层**：把这些规则写进 `SKILL.md`，让 AI 助手在用户描述目标时自动套用。

这第三层很关键。因为大部分创作者不想背 Seedance 2.0 的文件上限、引用语法和镜头术语；他们只想说“帮我做一个电商产品展示视频”或“把这段舞蹈复刻成另一个角色”。Skill 的作用就是把用户意图翻译成平台能执行的提示词。

## 仓库结构：小，但目标明确

仓库结构非常简单：

| 文件 | 作用 |
|---|---|
| `README.md` | 英文介绍、安装方式、来源说明 |
| `README-zh.md` | 中文介绍、安装方式、来源说明 |
| `SKILL.md` | 英文版 Seedance 2.0 Prompt Writing Guide |
| `zh/SKILL.md` | 中文版 Seedance 2.0 视频提示词撰写指南 |
| `LICENSE` | MIT License |

README 推荐两种安装方式：

```bash
mkdir -p ~/.claude/skills
cp SKILL.md ~/.claude/skills/seedance-prompt-en.md
cp zh/SKILL.md ~/.claude/skills/seedance-prompt-zh.md
```

或者通过 skills CLI：

```bash
npx skills add dexhunter/seedance2-skill
```

这说明它不是一个普通“教程 repo”，而是面向 Agent runtime 的知识包。它默认用户会把技能装进 Claude skills 目录，之后让 Agent 直接调用。

## 第一层价值：把平台限制写进 Prompt 生成器

视频生成提示词最容易被忽视的部分，不是创意，而是平台约束。`seedance2-skill` 明确写了 Seedance 2.0 的输入限制：

| 输入类型 | 数量上限 | 格式 | 大小 / 时长限制 |
|---|---:|---|---|
| 图片 | ≤ 9 张 | jpeg、png、webp、bmp、tiff、gif | 每张 < 30MB |
| 视频 | ≤ 3 个 | mp4、mov | 每个 < 50MB，总时长 2–15 秒 |
| 音频 | ≤ 3 个 | mp3、wav | 每个 < 15MB，总时长 ≤ 15 秒 |
| 总文件数 | ≤ 12 个 | 多模态合计 | — |
| 输出视频 | 4–15 秒 | — | 480p 到 720p 范围 |

它还提醒：不支持写实真人脸部素材，系统会自动拦截；使用参考视频时生成成本略高；应该优先上传对画面或节奏影响最大的素材。

这类信息看似琐碎，但对 Agent 非常重要。一个不会约束输入的 Prompt Agent，很容易帮用户设计出“9 张图 + 4 段视频 + 2 个音频”的方案，然后在平台第一步就失败。好的 skill 应该先帮用户避免不可执行方案。

## 第二层价值：`@` 引用系统把素材变成可调度资源

Seedance 2.0 的一个关键能力是多模态输入。`seedance2-skill` 把 `@` 引用系统放在核心位置：

```text
@图片1 / @Image1
@视频1 / @Video1
@音频1 / @Audio1
```

但重点不是“能引用素材”，而是必须说明每个素材的作用。例如：

| 用途 | 示例 |
|---|---|
| 首帧 | `@图片1 作为首帧` |
| 尾帧 | `@图片2 作为尾帧` |
| 人物形象 | `参考 @图片1 的人物形象` |
| 场景背景 | `场景参考 @图片3` |
| 运镜 | `参考 @视频1 的运镜效果` |
| 动作编排 | `参考 @视频1 的动作编排` |
| 音乐节奏 | `背景 BGM 参考 @音频1` |
| 产品外观 | `产品细节参考 @图片3` |

这其实是在把素材库变成一个可编排的 production graph。图片不再只是“上传的图”，而可以分别承担首帧、尾帧、角色、服装、场景、产品细节等角色；视频不再只是参考视频，而可以拆成运镜、动作、特效、节奏、声音等可复刻维度。

对 QCut 这类产品来说，这一点很关键。未来的视频创作界面不应该只是一个 Prompt 输入框，而应该允许用户明确指定：这张图锁角色，那段视频锁运镜，这个音频锁节奏，那张图锁产品外观。Skill 只是文本形态的前身。

## 第三层价值：把 Prompt 写成分镜脚本，而不是形容词堆叠

仓库里的基本公式是：

```text
[主体/人物设定] + [场景/环境] + [动作/运动描述] +
[运镜语言] + [分时段描述] + [转场/特效] +
[音频/音效设计] + [风格/氛围]
```

对于 10 秒以上的视频，它建议用分时段结构：

```text
0–3秒：开场画面、运镜、动作
3–6秒：中段发展
6–10秒：高潮或关键动作
10–15秒：收尾、定格画面、品牌文字
```

这和普通图像 Prompt 很不一样。图像 Prompt 可以靠“高质量、电影感、8K、细节丰富”这类词堆出风格；视频 Prompt 如果只堆形容词，就很容易失控。因为视频的难点是时间：角色怎么动，镜头怎么动，动作如何承接，转场怎么发生，声音是否配合。

所以好的视频 Prompt 更像一个 15 秒导演脚本，而不是一句审美描述。

## 运镜语言是 AI 视频的“控制旋钮”

`seedance2-skill` 专门列出了一套运镜词表：推镜头、拉镜头、摇镜、跟拍、环绕、一镜到底、希区柯克变焦、鱼眼、低角度、俯拍、第一人称、快速摇镜、机械臂跟随，以及极致特写、面部特写、中景、全景、远景等景别。

这说明视频生成 Prompt 的核心正在从“画面里有什么”扩展到“摄影机怎么存在”。

同一个主体，用不同运镜会产生完全不同的结果：

- 产品广告需要静态镜头、悬浮拆解、缓慢旋转；
- 恐怖短片需要推镜、低角度、突然的视角变化；
- MV 需要卡点、节奏、镜头景别变化；
- 短剧需要跟拍、过肩、面部特写和对话节奏；
- 游戏 UI 需要一镜到底、界面展开、角色动作和面板同步。

如果 Agent 不懂这些词，它只能生成“看起来像视频的描述”；如果 Agent 掌握运镜语言，它才有可能帮用户写出可控的视频提示词。

## 场景模板：Skill 的真正产品价值

仓库里最实用的部分，是把 Seedance 2.0 的能力拆成场景模板：

1. **人物一致性**：用参考图锚定角色；
2. **运镜复刻**：参考已有视频的摄影机运动；
3. **创意模板 / 特效复刻**：复刻转场、广告创意、视觉特效；
4. **视频延长**：向后或向前延长已有视频；
5. **视频编辑**：保留视频主体，只改剧情、角色或元素；
6. **音乐卡点**：让图片序列按参考视频或音频节奏切换；
7. **对话与声音演绎**：写角色台词和语气；
8. **一镜到底**：连续无剪辑长镜头；
9. **电商 / 产品展示**：产品拆解、旋转、重组、食物质感；
10. **科普教育**：透明人体、血管、粒子、对比演示等。

这些模板的意义不是“用户可以复制粘贴”，而是 Agent 可以根据用户意图选择不同模板。

用户说“做一个汉堡广告”，Agent 应该调用产品展示模板；用户说“用这个舞蹈换成另一个人”，Agent 应该调用运镜/动作复刻模板；用户说“给这段短剧加后续”，Agent 应该调用视频延长模板；用户说“做一个科普短片”，Agent 应该调用分时段教育可视化模板。

这就是 skill 格式的优势：它把隐性经验变成可路由的操作模式。

## 和普通 Prompt 仓库的区别：它更接近“操作协议”

很多 Prompt 仓库的问题是：它们收藏的是结果，而不是方法。用户看到一堆漂亮 Prompt，但不知道为什么有效，也不知道怎么迁移到自己的素材上。

`seedance2-skill` 更接近操作协议，因为它回答的是：

- 输入素材怎么编号？
- 每个素材承担什么角色？
- 什么时候该用图片，什么时候该用视频？
- 10 秒以上怎么按时间拆？
- 如何描述运镜？
- 如何写转场、音效、台词？
- 哪些素材会被平台拦截？
- 哪些场景有固定 Prompt 骨架？

这类知识对 Agent 尤其重要。Agent 不需要记住某一句“酷炫 Prompt”，它需要知道遇到某类任务时应该怎样组织信息。

## 对 QCut 的启发：Prompt Skill 可以变成创作节点

如果把这个仓库放到 QCut 的产品视角，它暗示了一个很自然的方向：把 Prompt Skill 从文档变成创作节点。

例如：

- **角色一致性节点**：输入角色图，输出带 `@图片1` 锚定语的视频 Prompt；
- **运镜复刻节点**：输入参考视频，自动生成“参考 @视频1 的运镜和动作编排”；
- **视频延长节点**：输入尾帧或原视频，生成 5/10/15 秒延长 Prompt；
- **产品展示节点**：输入商品图，输出拆解、旋转、重组、质感描述；
- **音乐卡点节点**：输入音频和多张图，输出按节拍切换的 Prompt；
- **科普可视化节点**：输入主题，输出按时间段推进的教学镜头。

这比让用户自己在一个文本框里写 Prompt 更可靠。文本 Skill 是第一步，下一步应该是 UI 化和 graph 化：每个模板都变成一个可配置模块，最后自动合成为 Seedance 2.0 可执行提示词。

## 对 Agent Skill 生态的启发

这个仓库也说明了 Agent Skill 的一种理想形态：

1. **不是泛泛介绍工具，而是写清楚平台约束**；
2. **不是只给示例，而是给可组合的结构公式**；
3. **不是只服务人类阅读，而是让 Agent 能在任务中调用**；
4. **最好同时提供中英文版本，适配不同创作者环境**；
5. **把安装路径、触发场景、输入输出都写清楚**。

当然，它也还有继续增强的空间。例如可以加入更严格的 JSON 输出 schema、失败诊断表、按行业分类的模板索引、真实案例的 A/B 对比、以及 QCut / ComfyUI / 即梦网页端的端到端操作步骤。

但作为一个轻量 skill，它已经抓住了正确方向：**把模型使用经验产品化。**

## 我的判断：AI 视频创作的下一层是“Prompt Ops”

过去大家谈 Prompt Engineering，更多是在谈“怎么写一句更有效的话”。但视频生成正在把问题变复杂：它涉及素材选择、引用角色、镜头语言、节奏、声音、时长、平台限制、合规限制、成本和失败重试。

所以 AI 视频真正需要的是 Prompt Ops：

- 把提示词模板版本化；
- 把平台限制写入工具；
- 把素材引用变成结构化资源；
- 把分镜和运镜变成可编辑字段；
- 把成功/失败案例沉淀为 Skill；
- 让 Agent 负责从用户意图生成可执行方案。

`seedance2-skill` 虽然只是一个小仓库，但它代表的方向很清楚：未来的视频 Prompt 不会只是散落在文档里的“金句”，而会变成 Agent、创作工具和视频平台之间的一层操作系统。

对 QCut 这种 AI 视频生产工具来说，这正是值得吸收的部分：不要只做 Prompt 输入框，要做 Prompt 可以被组织、验证、复用和自动执行的生产系统。
