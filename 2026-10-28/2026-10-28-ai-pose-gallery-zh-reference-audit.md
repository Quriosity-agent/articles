“让角色换成这个姿势”，往往比写一大段肢体描述更直接。但这里有三个不同的问题：有没有合适的参考图，生成工具能不能准确跟随，以及参考素材究竟允许怎样使用。

AI Pose Gallery 中文版主要解决第一个问题。它把日文姿势元数据翻译成中文，并保留原站已有的筛选、分组、多角度切换和图片下载功能。它是一套静态参考图库，没有训练新的姿势模型，也不是可以拖关节、导出骨骼的 3D 编辑器。

原项目包含成人向分类。本文只讨论数据组织、一般姿势参考和前端实现，不展示这些分类的素材。由于原站明确限制图片数据再分发，本文也不转载原始姿势图，改用独立统计图说明规模。

使用时可以把角色身份、姿态、服装分开指定：姿势图负责肢体与构图，另外的角色图负责人物，服装参考负责穿搭。站点建议用这种参考方式，但它没有在网页里执行姿态迁移。先用一张普通站姿检查重心、手脚和遮挡，再测试换角度是否稳定，比一次下载全库更能判断适不适合自己的工具。服装参考的分工另见 [AI Costume Gallery](../2026-10-29/2026-10-29-ai-costume-gallery-outfit-reference.md)。这仍是建议流程，本次没有进行生成实验。

## 1. 1439 张图片，实际对应 288 个姿势组

前端按“体系＋姿势编号”分组，而不是把每张图片当成一个新姿势。本次结构化核对得到：

| 项目 | 实际含义与结果 |
|---|---|
| 姿势组 | 288 组 |
| 图片／视角记录 | 1439 条，ID 均唯一 |
| 图片文件引用 | 每条记录一张缩略图、一张原图，共 2878 条不同路径，均存在于 Git 文件树 |
| 视角覆盖 | 287 组有五个视角，一组只有四个 |
| 分类与视角类型 | 26 个分类、五种视角标签 |
| 名称去重 | 日文姿势名 288 个，中文译名 287 个 |

最后一项不是少了一组数据。两个不同的日文名称被译成了同一个中文名称“前倾・手扶膝”，而分组键和 ID 仍保留。因此，记录参考时最好保存 ID 与视角，不要只存中文名称。

也不要把 2878 个文件理解成 2878 种动作：它包含同一张参考的缩略图与原图。原图规格在项目说明和灯箱中标为 900×1200，但本次没有下载、逐张解码全部图片，不能据此宣布所有文件的内容和尺寸均已通过检测。[数据审计结果](imgs/ai-pose-gallery-zh-reference-audit/data-audit.json)、[分组实现](https://github.com/anhao/ai-pose-gallery-zh/blob/072a3690af6e7e0011abbe0fa1ccc08939fbb47d/index.html)

## 2. 中文版的价值，是把文件变成能快速查找的参考

核心页面是一个 HTML 文件。它用 `fetch('data/pose-zh.json')` 读取中文记录，在浏览器里建立姿势组和检索串，再按体系、分类、视角与关键词组合过滤。

“按姿势分组”适合先选动作，再比较角度；“逐张浏览”适合寻找特定画面方向。卡片允许切换缩略图，灯箱则先显示小图，再异步加载原图。代码还用递增标记避免快速切换时，上一张迟到的加载结果覆盖当前图片。

这些细节解释了图库为什么好查找：它减少了重复卡片，把同一动作的视角放在一起，并保留 ID，方便回到同一条记录。其中分组、角度筛选与下载在日文原站也有，中文版额外降低了中文用户理解名称与检索的成本。检查版本的检索是本地字符串匹配，不是理解自然语言动作的语义搜索，也没有向量检索服务。[页面源码](https://github.com/anhao/ai-pose-gallery-zh/blob/072a3690af6e7e0011abbe0fa1ccc08939fbb47d/index.html)、[翻译回填脚本](https://github.com/anhao/ai-pose-gallery-zh/blob/072a3690af6e7e0011abbe0fa1ccc08939fbb47d/scripts/apply_translation.py)

## 3. 多角度参考，不等于三维资产或连续动作

五个角度仍然是五张二维图片。检查的资料结构保存的是名称、角度和图片路径，没有网格、关节坐标、骨骼层级、相机标定或动作时间轴。

因此，它可以帮助选择构图、重心和肢体摆放，但不能直接导出角色 rig，也不能证明不同视图在几何上严格一致。将一张图送进支持姿势参考的生成工具，实际跟随程度仍由那个工具决定。若某条工作流需要骨架图、深度图或动画，还需要额外的提取、建模或绑定步骤。

一个一般创作试用可以很小：选一组普通站姿，保存 ID 和视角；把角色身份、服装、背景作为另外的条件；只改变姿态，检查手脚、支撑关系和遮挡是否合理。这是本文建议的验收方式，本次没有调用模型验证换姿效果。

## 4. “代码开源”与“图片可再分发”必须分开

原站注意事项允许免费用于作品制作，包括商业作品、编辑和参考，但明确禁止对图片数据本身及加工后的图片数据进行再分发、转载或再售。这不是一份允许任意镜像素材库的开放数据许可。[原站注意事项](https://ai-pose-gallery.pages.dev/)

中文版对此也保留了区分：仓库 `LICENSE` 说明 MIT 仅适用于代码，不覆盖图片和原始数据。不过，当前文本还存在不一致：`LICENSE` 对这些素材写有“不得用于商业用途”，页面帮助却转述原站允许商业作品参考。不能只挑其中一句，就替所有用途下结论。[仓库许可](https://github.com/anhao/ai-pose-gallery-zh/blob/072a3690af6e7e0011abbe0fa1ccc08939fbb47d/LICENSE)

更需要单独确认的是镜像与批量发布。原站允许拿图做作品参考，不自动等于允许把整套图片放进自己的公开仓库；中文版帮助文字本身也注明，镜像公开展示与转载授权需要维护者另行确认。本次没有取得或验证额外授权文件，因此不对镜像是否获得许可作肯定或否定判定。

对于读者，稳妥的区分是：借鉴画廊代码，查看具体图片的原作者条款，确认自己的用途；不要把 MIT 代码许可当成训练数据、素材包、模板预装或整库再发布的授权。以上是已读条款之间的关系说明，不替代具体项目的权利核查。

## 5. 静态站轻量，但“零依赖”不等于零外部请求

检索和分组不需要后端数据库，也不需要前端框架构建。但页面通过 `fetch` 读取 JSON，仍应使用 HTTP 环境，不能把“静态”理解为双击 HTML 必然可用。源码自己的失败提示也要求检查 HTTP 访问与数据文件。

当前提交末尾另外加载了一个外部访问统计脚本。因此，“图库数据可静态托管”不等于这个版本加载时完全不联系外部服务。本次没有分析其具体上报内容；有离线或隐私要求的部署，需要另行审查这一依赖。[固定版本 HTML](https://github.com/anhao/ai-pose-gallery-zh/blob/072a3690af6e7e0011abbe0fa1ccc08939fbb47d/index.html)

`verify.py` 检查文件存在、最低大小和 JPEG／PNG 文件头，并不完整解码图片，也不验证解剖、视角一致性或授权。即使它显示通过，也只说明这些有限的文件规则通过。[校验脚本](https://github.com/anhao/ai-pose-gallery-zh/blob/072a3690af6e7e0011abbe0fa1ccc08939fbb47d/scripts/verify.py)

## 6. 本次验证到哪里

本次读取了帖子、中文源码、日文原站的公开说明，以及两份 JSON 元数据。独立审计脚本的八项结构检查全部通过：包括记录数、ID 唯一性、分组数、原始顺序与路径保留、图片路径唯一性及 Git 跟踪情况、四／五视角组的分布。

这不是“1439 张图片质量全部合格”。10 月 28 日的源码审计使用稀疏检出，没有拉取全部图片，也没有运行整库下载器或启动图库 UI；10 月 29 日的补核实际操作了日文原站的标准站姿筛选、侧面角度、编号搜索和单张放大图。两次均未逐张审图或进行 AI 生成测试，也未验收中文版的实时 UI。只发布原创统计图与汇总结果，不复制原始数据集。复现方式见 [SOURCES.md](imgs/ai-pose-gallery-zh-reference-audit/SOURCES.md)。

这类图库的价值是降低寻找和复用姿势参考的成本。中文检索、稳定 ID 和视角分组都值得借鉴；三维一致性、生成模型跟随程度和素材使用权，则是另外三件需要验证的事。
