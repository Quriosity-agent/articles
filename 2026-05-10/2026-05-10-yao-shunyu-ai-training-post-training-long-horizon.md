这期访谈最有价值的地方，不是又多了一段「某个明星研究员参与了哪个模型」的故事，而是把 2026 年大模型竞争的真实重心讲得很直白：**模型公司正在从“谁的榜单更高”，转向“谁能定义下一个可训练的问题，并把数据、环境、基础设施、组织协作做成一个稳定系统”。**

姚顺宇的履历本身很适合做这个观察窗口：清华物理本科，斯坦福理论高能物理与量子信息方向，短暂 Berkeley postdoc 后转入 Anthropic，参与 Claude 3.7 相关的后训练与 agentic coding 工作；随后加入 Google DeepMind / Gemini。他既不是纯产品视角，也不是单纯的算法论文视角，而是站在工业级模型训练系统内部看问题。

## 一句话结论

这场访谈可以压缩成五个判断：

1. **顶级模型的纸面差距正在缩小。** OpenAI、Anthropic、Gemini 之间仍有体验差异，但公开 benchmark 越来越难解释真实差距。
2. **后训练不是“补丁”，而是第二个可扩展范式。** 关键不是某个神秘算法，而是能否找到回馈信号清晰、数据干净、可稳定训练的环境。
3. **Coding 是工具使用和环境交互的最好训练场之一。** 它有清晰反馈、有足够数据，也能反过来提高模型公司的研究效率。
4. **下一个问题是 long horizon。** 真正难的是让模型跨更长时间、更多上下文、更多状态变化持续工作。
5. **组织能力已经变成模型能力的一部分。** “靠谱、做事细、负责任”听起来朴素，但在大规模训练系统里，它直接决定指标是否可信、实验是否可复现、训练是否稳定。

## 1. AI 进入的不是“下半场”，而是“定义问题”的阶段

访谈开头，主持人问 AI 是否进入了某种“下半场”。姚顺宇没有沿用这个说法，而是给了一个更工程化的判断：今天大家已经不太担心“AI 能不能做得到”，更担心“这件事有没有被良好定义”。

这句话很关键。

过去两年，很多竞争还可以用公开榜单表达：SWE-bench、AIME、IMO、各类 reasoning / coding benchmark。模型之间的差异可以通过数字被“纸面化”：谁强一点，谁弱一点，谁擅长数学，谁擅长代码。

但当公开 benchmark 被快速打满，或者测试题本身开始变得不够良好定义，榜单就不再是战略方向。继续刷榜当然还有市场价值，但它越来越像模型公司的“卫生指标”：你不能没有，但只靠它无法赢。

于是竞争重心发生迁移：

- 不是证明模型“聪明”；
- 而是找到下一类值得训练的任务；
- 并把任务变成可评估、可采样、可学习、可稳定扩展的环境。

这也解释了为什么姚顺宇反复强调 make bet。大公司和 startup 的打法不同，但共同点都是：必须对“下一步该教模型什么”下注。

## 2. Claude 3.7 的分水岭：后训练从修修补补变成可规模化工程

访谈中最硬核的部分，是关于 Claude 3.7、agentic coding 和大尺度强化学习的讨论。

姚顺宇提到，在 Claude 3.7 之前，后训练更像是“小规模、修修补补”的阶段。真正的变化，是大家开始意识到后训练可以 scale up：找到合适环境，让环境提供足够清晰的反馈信号，同时环境本身也是强数据源，训练就能稳定起来。

这其实把“后训练神话”拆开了。外界常常期待某个秘密算法、某个 RL trick、某个不可公开的 recipe。但姚顺宇的表达更像工业系统视角：

> 把简单的事做得比谁都干净，才是最关键的。

在强化学习里，复杂算法当然存在；但复杂度会带来基础设施、采样、训练稳定性、异步架构、数值差异等问题。某个 lab 的 trick 之所以有效，往往不是因为它脱离系统后仍然有效，而是因为它刚好适配那套数据、采样、训练器、评估、调度和组织流程。

这点对今天很多 AI 创业公司尤其重要：**不要迷信“某家怎么做 RL”的单点答案。现代模型训练不是菜单式 recipe，而是一个耦合系统。**

## 3. 为什么 coding 这么重要：它不是垂直场景，而是 agent 能力的抽象

访谈里，姚顺宇对 coding 的解释很值得单独摘出来。

他认为 coding 重要有两个原因：

第一，coding 本身能提升模型公司的研究效率。一个更会写代码、调试、调用工具的模型，会反过来加速研究流程，形成内部飞轮。

第二，coding 是模型“使用工具并与环境交互”的好抽象。它同时具备几个稀缺条件：

- 反馈信号清晰：测试能不能过、代码能不能跑、错误在哪里；
- 数据相对充足：开源代码、issue、patch、提交历史、测试用例都可形成训练材料；
- 环境交互自然：模型不仅生成文本，还要读文件、改代码、跑命令、观察结果、迭代修复；
- 可迁移到更通用的 agent 能力：规划、工具调用、错误恢复、状态管理。

所以 Cursor 的兴起并不只是“一个壳包住 Claude”。它让软件工程圈第一次大规模体会到：agentic coding 不是 demo，而是真能改变工作流的效率工具。

这也解释了为什么模型公司会把 coding 当成战略高地。它既是产品入口，又是训练环境，还是研究效率杠杆。

## 4. 预训练没有结束，后训练也没有结束；真正短缺的是“下一门课”

外界经常把 2025-2026 的模型进展讲成“预训练 scaling law 到头了，所以后训练接棒”。访谈里姚顺宇给了更细的说法：他一度也觉得 pre-training party is over，但后来发现预训练和后训练都还有空间。

预训练的价值不只是“继续变大”，而是一套系统框架：告诉你在什么数据、什么算力、什么配比下更有效。Google 在这个阶段的优势也很明显：当预训练越来越像确定性工程项目，它就进入了 Google 的舒适区——工程管理、清晰节点、系统评估、可控推进。

后训练则更像探索空间。它的数据分布更窄，但质量要求更高。预训练需要覆盖广；后训练需要把某些高价值任务教得非常准。

这里最有意思的比喻是：模型像一个非常聪明的小孩。现在问题不是教不会，而是人类老师还不知道下一门课该是什么、该怎么教。

已经被教过的课包括 chatbot、coding、部分 reasoning。下一门课可能是 ML coding、long horizon、多模态生成、持续学习、世界模型，但这些概念很多仍然定义模糊。

## 5. Long horizon：下一代 agent 的真正门槛

在访谈尾声，姚顺宇明确说，如果基于当下认知选一个重要 bet，他会选 **long horizon**。

这和最近很多 agent 产品的真实瓶颈完全对得上。今天的模型可以在短上下文里表现得很聪明，也可以完成单次代码修改、单轮工具调用、单个搜索任务。但一旦任务变成：

- 多小时甚至多天执行；
- 中间要记住目标和约束；
- 要处理外部环境变化；
- 要在失败后恢复；
- 要把临时上下文沉淀成可复用状态；
- 要决定什么时候继续、什么时候停止、什么时候请求人类介入；

模型能力就不只是“下一 token 预测”或“单次 reasoning”了，而变成一个完整系统问题。

姚顺宇把 continuous learning、context management、甚至某些世界模型讨论都和 long horizon 放在一起看，这个视角很好：它们表面上是不同技术路线，本质上都是为了让模型在长时间跨度里维护状态、更新认知、持续行动。

对应用层创业公司来说，这意味着 agent 产品不能只赌模型变强。真正的产品差异会来自：任务分解、记忆、状态管理、权限边界、回滚机制、可观测性、人机协作协议。

## 6. 组织能力为什么会进入模型能力本身

这期访谈最反直觉的一点，是姚顺宇对“人”的判断非常朴素。他说这个行业最重要的特质不是“聪明”，而是：靠谱、做事细、对自己做的事负责任。

放在大模型训练里，这不是鸡汤。

因为每一个评估框架都可能被 hack。一个指标变好，可能是真进步，也可能是数据泄漏、环境偏差、评估污染、采样差异、异步训练副作用、题目定义问题。只有可靠的人，才会主动追问：这个效果在大尺度上还成立吗？我们有没有漏掉某个因素？这个漂亮数字是不是只是局部 hack？

这也是为什么组织结构很重要。Anthropic 的优势之一，是在关键阶段能够更 top-down 地 make bet；Google 的优势，是把确定性范式做成工程项目；OpenAI、DeepMind、Anthropic 在预训练、后训练、产品之间的组织切法不同，也会影响它们看见问题、定义问题、推进问题的方式。

换句话说，模型不是只由 GPU、数据和算法训练出来的；它也由组织训练出来。

## 7. 对创业者和工程团队的启发

这期访谈对 AI 创业者的启发，可以总结成几条：

**第一，不要只看榜单。** 榜单能说明基础能力，但无法说明一个模型能否稳定嵌入真实工作流。

**第二，优先选择反馈信号清晰的场景。** Coding 为什么重要？因为能跑、能测、能迭代。其他行业如果想做 agent，也要找到自己的“测试用例”和“环境回馈”。

**第三，把数据和环境一起设计。** 后训练不是收集一堆偏好数据就结束了，而是要构造模型能反复试错、获得反馈、稳定学习的环境。

**第四，系统能力比单点 trick 更重要。** 训练、评估、采样、基础设施、产品反馈、人类标注、组织协作是一个整体。

**第五，尽早布局 long horizon。** 真正值钱的 agent，不是能回答一个问题，而是能在长任务里保持目标、管理状态、持续推进。

## 结语：下一轮竞争，是“教什么”和“怎么教”

如果说 GPT-4 之前的竞争，是谁能把互联网规模语料和算力变成更强的通用模型；Claude 3.5/3.7 之后的竞争，是谁能把后训练和工具使用做成可规模化能力；那么下一轮竞争可能就是：谁能定义下一个值得教给模型的世界。

这件事听起来像研究判断，实际上也是产品判断、组织判断、工程判断。

模型公司要回答：下一门课是什么？

应用公司要回答：我的产品能不能把真实任务变成可反馈、可学习、可持续执行的环境？

而对个人来说，姚顺宇给出的答案也很简单：在 AI 浪潮里，个人当然重要，但更重要的是能不能在浪里把事情做干净、做可靠、做成系统。
