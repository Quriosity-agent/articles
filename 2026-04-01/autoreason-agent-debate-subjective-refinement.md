# AutoReason：当 AI 没有分数可以优化时，让 Agent 互相辩论

![AutoReason 流程图](autoreason-diagram.jpg)

> **TL;DR**: AutoResearch 通过 val_bpb 等客观指标驱动迭代优化——但写作、论证、营销文案这些主观任务没有数字可以衡量。SHL0MS 构建的 AutoReason 用 **agent 辩论** 替代客观适应度函数：隔离的 agent 各司其职——批评者只找问题、作者只管重写、合成者融合优势、盲审团做最终裁决。测试结果：盲审面板 **35/35 满分**，第二名方法只拿到 **21/35**。这就是把科学同行评审搬进了 AI 生成循环。

---

## 📖 问题：AutoResearch 到头了？

Karpathy 的 [autoresearch](https://github.com/karpathy/autoresearch) 是 2026 年最优雅的 AI 研究范式之一：让 agent 修改训练代码 → 跑 5 分钟 → 看 val_bpb 有没有降 → 保留或回滚 → 循环。

核心在于那个 **val_bpb**——一个冷冰冰的数字。数字降了，就是进步。简单、可靠、无争议。

但现实中大多数任务**没有**这样一个数字：

- 这段营销文案够不够有说服力？
- 这篇论证够不够有力？
- 这个设计方案够不够优雅？
- 这份策略报告够不够有洞察力？

你没法对"说服力"跑一个 loss function。让同一个 LLM "改进"自己的输出，只会得到三种失败模式：

1. **谄媚模式**——要求它"改进"时，它只做表面润色，不敢推翻自己
2. **过度批判模式**——要求它"找问题"时，鸡蛋里挑骨头，把好的部分一起否定
3. **和稀泥模式**——要求它"融合两个版本"时，取最大公约数，棱角全部磨平

**单 agent 迭代在主观领域行不通。** 你需要的不是一个更聪明的 agent，而是一个更好的**流程**。

---

## 🔄 AutoReason 循环：结构化辩论

SHL0MS 的 AutoReason 把科学界的同行评审机制搬进了 AI 生成流程。核心思想：**用辩论替代分数**。

整个循环分 7 步：

### Step 1：生成 Version A（初始草稿）

第一个 agent 根据任务需求生成初始版本。没什么特别的，就是常规的 LLM 生成。

### Step 2：稻草人攻击

一个**全新的 agent**（没有看过生成过程，只看到成品）对 Version A 发起纯批评。

关键规则：**只找问题，不提修复方案。**

为什么？因为当你让 LLM 同时批评和修复时，它会陷入谄媚模式——批评变得温和，修复变成微调，本质上没有推翻任何东西。把"批评"和"修复"拆开，批评才能真正犀利。

### Step 3：盲写 Version B

另一个独立的 agent 只看到三样东西：原始任务需求 + Version A + 批评意见。它**看不到**批评者的完整上下文和推理过程。

它的任务是根据这些信息从头写一个 Version B——不是在 A 上打补丁，而是重新构思。

### Step 4：合成 Version AB

第三个 agent（对 A 和 B 的创作过程一无所知）同时看到两个版本作为**平等输入**，合成出 Version AB——取两者的精华，创造一个新的融合版本。

### Step 5：盲审裁决

一个**全新的评审团**（完全新的上下文，没有参与过前面任何环节）同时看到 A、B、AB 三个版本——**标签随机化**，评审团不知道哪个是原版、哪个是改进版、哪个是合成版。

评审团选出最强版本。

### Step 6：赢家成为新的 A

被选中的版本成为下一轮的 Version A，循环回到 Step 2。

### Step 7：收敛即停止

当评审团**持续选择当前版本**（即没有任何新版本能击败它）时，循环结束。不需要人工设定"跑几轮"——系统自己知道什么时候够好了。

---

## 🧊 为什么隔离是关键

AutoReason 最优雅的设计在于：**每个 agent 都在全新的上下文中工作**。

没有共享记忆。没有对话历史。没有"我之前说过……"。

这不是偷懒，这是**刻意设计**：

| 角色 | 看到什么 | 看不到什么 |
|------|---------|-----------|
| 批评者 | Version A 的成品 | 生成过程、任务的完整意图 |
| 重写者 | 任务 + Version A + 批评 | 批评者的推理过程 |
| 合成者 | Version A + Version B | 谁先谁后、谁是"原版" |
| 评审团 | 三个标签随机的版本 | 任何版本的来源和历史 |

这解决了三个 LLM 的核心弱点：

- **批评者只批评** → 没有谄媚的空间
- **重写者独立重写** → 不会被批评者的偏见带跑
- **评审团真正盲审** → 消除了确认偏差和锚定效应

这和科学界的同行评审是一模一样的逻辑：审稿人不知道作者是谁（双盲），审稿意见不包含修改后的论文（只批评不修复），最终的编辑决定由独立的编辑做出（不是审稿人自己决定录不录用）。

**数学用证明，科学用同行评审，AutoReason 用 agent 辩论。** 不同领域，同一个底层思想：通过对抗性验证逼近真理。

## 📊 结果：压倒性优势

在盲审测试中：

- **AutoReason：35/35**（满分）
- **次优方法：21/35**

差距不是微小的——是 **67% 的提升**。

这意味着在主观质量评估中，AutoReason 的输出在每一次盲审对比中都被选为最优。结构化辩论不是略好于单 agent 迭代——是**碾压级别的好**。

## 🛠️ 实际应用场景

AutoReason 的框架可以直接应用到任何"没有客观分数"的 AI 生成任务：

- **内容写作** — 文章、博客、技术文档的质量迭代
- **营销文案** — A/B 测试前的文案优化（让 agent 先辩论，再给人看）
- **论证构建** — 法律论证、学术论文、辩论准备
- **产品设计** — 设计方案的对抗性评审
- **战略规划** — 商业策略的多角度压力测试
- **代码审查** — 不是"有没有 bug"而是"这个架构设计好不好"的主观判断

核心价值：**把 AutoResearch 的"客观迭代"扩展到了"主观迭代"**。AutoResearch 告诉你 val_bpb 从 0.862 降到了 0.858——AutoReason 告诉你"这个版本在盲审中击败了所有对手"。

## 🦞 龙虾裁决

AutoReason 最让我兴奋的不是技术细节——是它验证了一个古老的认知论原则：**真理不是被发现的，是被辩论出来的。**

科学革命不是因为某个天才突然看到了真相，而是因为同行评审制度让错误的想法无处藏身。AutoReason 把同样的机制搬进了 AI 系统：不是造一个更聪明的 agent，而是造一个更好的辩论场。

角色隔离的设计特别精妙——它承认了 LLM 的本质弱点（谄媚、过度批判、和稀泥），然后不是试图"修复"这些弱点，而是**用流程设计绕过它们**。这比任何 prompt engineering 技巧都高明。

35/35 vs 21/35 的结果说明了一切。在主观质量的竞技场上，多 agent 辩论 > 单 agent 迭代，差距还不小。

如果你在用 AI 生成任何需要"判断力"而非"计算力"的内容，AutoReason 的框架值得认真研究。不一定要完整实现——哪怕只是在你的 workflow 里加入"让一个独立 agent 攻击你的草稿"这一步，输出质量就会显著提升。

**辩论产生真知。Agent 也不例外。** 🦞
