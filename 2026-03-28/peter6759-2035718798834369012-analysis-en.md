## What Is gstack

gstack is Garry Tan's personal Claude Code workflow, open-sourced under MIT at [github.com/garrytan/gstack](https://github.com/garrytan/gstack). 26k+ stars in its first week.

The core idea: **define roles in Markdown, let AI act as different engineering team members**.

It includes 20+ slash commands covering:

- **CEO / Product**: `/office-hours`, `/plan-ceo-review`
- **Eng Manager**: `/plan-eng-review`
- **Designer**: `/plan-design-review`, `/design-consultation`
- **Code Reviewer**: `/review` (paranoid-level review)
- **QA Lead**: `/qa` (actually opens a browser and clicks through your app)
- **Security Officer**: `/cso` (OWASP + STRIDE audits)
- **Release Engineer**: `/ship`, `/land-and-deploy`, `/canary`

Garry claims 600K+ lines of production code (35% tests) in 60 days, 10-20K lines/day, part-time, while running YC full-time.

## Deep Dive: /office-hours

### What It Does

`/office-hours` simulates the YC office hours experience — you bring a fuzzy idea, and AI uses structured questioning to help you clarify it before writing any code.

### Two Modes

1. **Startup Mode** — Six forcing questions:
   - **Demand reality**: How many people *actually* need this?
   - **Status quo**: How do they solve it today?
   - **Desperate specificity**: Who needs it *most*?
   - **Narrowest wedge**: What's the absolute minimum v1?
   - **Observation**: What have you noticed that others haven't?
   - **Future-fit**: Does this still matter in 3 years?

2. **Builder Mode** — Design thinking brainstorm for side projects, hackathons, and open source.

### Why It Matters

The key insight: **it doesn't give you answers — it forces you to think clearly about the problem**.

Most people use AI coding tools as "build me X." gstack's `/office-hours` flips this — before you write any code, it verifies that what you're building is worth building.

From the README:

```
You: I want to build a daily briefing app for my calendar.
Claude: [asks about pain — specific examples, not hypotheticals]
You: Multiple Google calendars, stale info, wrong locations...
Claude: I'm going to push back on your framing. You said "daily briefing
        app." But what you actually described is a personal chief of staff AI.
        [extracts 5 capabilities you didn't realize you were describing]
        [challenges 4 premises — you agree, disagree, or adjust]
        [generates 3 implementation approaches with effort estimates]
        RECOMMENDATION: Ship the narrowest wedge tomorrow.
```

## Deep Dive: /plan-ceo-review

### What It Does

`/plan-ceo-review` switches Claude into CEO/founder mode, running an **11-dimension structured review** of your feature or product plan.

### The 11 Dimensions

| # | Dimension | What It Covers |
|---|-----------|----------------|
| 1 | Architecture | Is the system design sound? |
| 2 | Error Handling | Every error path mapped? |
| 3 | Security | High-severity issue flagging |
| 4 | Data/UX | Edge cases handled? |
| 5 | Quality | Code quality issues |
| 6 | Testing | Coverage diagram + gap analysis |
| 7 | Performance | Bottleneck identification |
| 8 | Observability | Logging/monitoring in place? |
| 9 | Deployment | Release risks |
| 10 | Future | Reversibility score + tech debt inventory |
| 11 | Design | UI issues (skippable) |

Output is a comprehensive MEGA PLAN REVIEW table showing findings count, gaps, and severity per dimension.

### Four Review Modes

- **EXPANSION** — agrees to scope expansion
- **SELECTIVE** — cherry-picks recommendations
- **HOLD** — maintain current scope
- **REDUCTION** — cut features

### The Inspiration

Garry says this is inspired by Brian Chesky's (Airbnb CEO) "10-star product experience" thinking. Unlike a consultant who gives opinions, `/plan-ceo-review` runs a **structured evaluation framework** on an AI that can research your market in real-time.

## Why These Two Skills Matter Most

1. **Zero code, pure thinking tools**: You don't need gstack installed to steal these ideas. Embed the questioning frameworks into your own system prompts.

2. **They solve AI coding's biggest problem**: Everyone's chasing "write faster." But the real bottleneck is "think clearer." These skills address the *thinking* problem.

3. **Replicable methodology**: The six forcing questions and 11-dimension review framework apply to any product or feature, not just Claude Code.

## Builder Takeaways: How to Apply This

### Without Installing gstack

Add the core questioning framework to your CLAUDE.md or system prompt:

```markdown
## Before any new feature, answer:
1. Who desperately needs this? (Name one specific person)
2. How do they solve it today? Why isn't that good enough?
3. How narrow can v1 possibly be?
4. How will you measure success?
```

### With gstack Installed

```bash
# Install (30 seconds)
git clone --depth 1 https://github.com/garrytan/gstack.git ~/.claude/skills/gstack
cd ~/.claude/skills/gstack && ./setup

# Use
/office-hours        # bring your idea
/plan-ceo-review     # review an existing plan
```

Works with Claude Code, Codex, and any agent supporting the SKILL.md standard.
