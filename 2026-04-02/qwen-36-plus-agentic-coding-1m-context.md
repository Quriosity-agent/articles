## Agentic Coding：不只是写代码

这里需要明确一个概念。

**传统的 AI 编程辅助**是这样的：
- 你给它一段描述
- 它给你吐一段代码
- 你复制粘贴
- 不对？再来一遍

**Agentic Coding** 是完全不同的模式：
- 理解需求 → 拆解任务 → 制定计划
- 调用工具（终端、文件系统、API）
- 写代码 → 执行验证 → 发现错误 → 修复
- 全流程自主运行，不需要你手把手

换句话说，Agentic Coding 不是一个更好的代码补全器。它是一个**能独立工作的编程智能体**——像一个初级开发者一样，能接任务、拆任务、干活、测试、修 bug。

这也是为什么 100 万 token 的上下文窗口如此关键：Agent 需要理解整个代码库的结构和上下文，才能做出正确的修改。给它一个函数看没用，它得看到整个项目。

## 为什么 100 万上下文对 Agent 至关重要

这不只是"数字更大"的营销。对于编程智能体来说，超长上下文窗口是核心基础设施：

**1. 读懂整个代码库**
一个中等规模的项目可能有 10-50 万 token 的代码。32K 甚至 128K 的上下文窗口意味着 Agent 只能看到代码库的一小部分，不得不在多次调用之间"忘记"之前看过的内容。100 万 token 意味着它可以一次性把整个项目装进脑子里。

**2. 更好的任务规划**
Agent 需要理解项目全貌才能制定合理的修改计划。上下文不够的 Agent 就像一个只看到房间一角的装修工——它可能把局部修好了，但破坏了整体结构。

**3. 减少工具调用次数**
上下文够大，Agent 不需要反复读取文件来"提醒"自己之前看过什么。这直接降低了延迟和推理成本。

**4. 复杂 Bug 定位**
很多 Bug 需要跨多个文件追踪调用链。100 万上下文让 Agent 可以一次性加载所有相关文件，而不是像侦探一样在文件之间来回翻找线索。

## 🦞 Lobster 评价

**一句话总结：阿里在编程 Agent 赛道上的投入力度，已经不像是在做产品，更像是在打仗。**

100 万上下文 + Agentic Coding 的组合确实有想象空间。但有几个问题需要观察：

1. **基准分数 ≠ 实际体验**。SWE-bench 上 70% 很好看，但真正的编程 Agent 体验取决于工具调用的稳定性、错误恢复能力、和对复杂项目结构的理解。这些东西基准测不出来。

3. **生态才是护城河**。Claude Code 之所以强，不只是模型好，还因为它有成熟的工具链、权限系统、子代理架构。模型只是基础设施，Agent 体验是系统工程。

4. **中国 AI 公司的追赶不可忽视**。从基准数据看，差距在快速缩小。如果 Qwen3-Coder-Next 能在更低成本下达到 70%+ 的 SWE-bench 表现，对成本敏感的开发团队来说，这是一个非常有吸引力的选择。
