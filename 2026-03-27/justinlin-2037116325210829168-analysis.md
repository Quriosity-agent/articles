## 背景

3 月 4 日，林俊旸发出那句「me stepping down. bye my beloved qwen」后，在社交媒体上沉默了三周。今天他发布了离职后的第一篇长文。没聊离职原因，没回应去向传闻，全文只做了一件事：**写下他对 AI 下一阶段方向的判断。**

核心论点一句话：**从「让模型想得更久」到「让模型边做边想」。**

## 六个关键观点拆解

### 1. o1 和 R1 教会我们的不是「推理」，是基础设施

第一波推理模型（OpenAI o1、DeepSeek R1）真正证明的不仅是「思考」可以作为训练目标，更重要的是：**要在语言模型上跑好 RL，反馈信号必须是确定的、可规模化的。** 数学、代码、逻辑这些可验证领域成了 RL 主战场，因为奖励信号质量远高于人类标注偏好。

一旦模型开始跑长推理轨迹，RL 就从 SFT 上面的薄层变成了系统工程——大规模 rollout、高吞吐验证、稳定策略更新。**第一个大转变：从扩展预训练到扩展推理后训练。**

### 2. 合并思考与指令模式——比想象中难得多

Qwen3 尝试把思考模式和指令模式统一到一个模型里：支持调节推理力度（低/中/高），甚至让模型自动判断该想多久。

**但真正的难点在数据，不在模型架构。** 两种模式要的数据分布和行为目标本质上互斥：

- **指令模式** 要求干脆利落，回复短、格式规范、延迟低——企业批量任务的刚需
- **思考模式** 要求多花 token，探索不同路径，保持足够内部计算来提升准确率

数据没策展好，结果就是两头平庸。所以 Qwen 2507 版本最终还是发了独立的 Instruct 和 Thinking 版本。而 Anthropic（Claude 3.7/4）和 DeepSeek V3.1 则走了集成路线。

**关键不在选哪条路，而在合并是否「自然长出来的」。** GPT 的 effort control 机制指向了正确方向：对计算的策略分配，而非开关切换。

### 3. Anthropic 的方向是有用的纠偏

推理链更长 ≠ 模型更聪明。很多时候冗长的推理链说明模型在**乱花算力**——什么都用同一种方式去想，不会分轻重缓急。

Anthropic 的 Claude 4 让推理可以跟工具调用交叉进行，把编程和 Agent 工作流放在最优先位置。核心思路：**思考应该由目标任务来塑造。**

写代码就帮你导航代码库、做规划、拆问题。跑 Agent 工作流就提升长周期执行质量。不是为了产出漂亮的中间文本。

### 4. 「智能体式思考」到底是什么

> **核心问题从「模型能不能想得够久」变成了「模型能不能用撑得起有效行动的方式来想」。**

智能体式思考要处理几件纯推理模型不用管的事：

- **什么时候该停止思考，开始动手**
- **该调哪个工具，先调哪个后调哪个**
- **环境反馈可能残缺、有噪声，得能用**
- **失败了得能改计划**
- **跨多轮对话和工具调用，思路不能断**

一句话总结：**智能体式思考，就是通过行动来推理。**

### 5. 智能体 RL 的基础设施为什么更难

推理 RL 里，rollout 基本是自己跑完的轨迹加一个干净的评估器。**智能体 RL 里，策略被塞进了一个大得多的系统：** 工具服务器、浏览器、终端、搜索引擎、沙盒、API 层、记忆系统、编排框架。环境不再是静态判分器，它是训练系统的一部分。

这带来两个关键变化：

1. **训练和推理必须更干净地解耦**——否则 rollout 吞吐量直接塌掉（编程 Agent 等执行反馈时 GPU 利用率远低于预期）
2. **环境质量成了一等研究对象**——SFT 时代拼数据多样性，Agent 时代拼环境的稳定性、真实性、覆盖面、反作弊能力

环境构建已经开始变成真正的创业方向了。

### 6. 下一个前沿：更有用的思考

林俊旸预判：**智能体式思考会成为主流，大概率替代掉大部分旧式的封闭推理。**

哪怕是极难的数学或编程任务，先进系统也应该能搜索、模拟、执行、检查、回头改。目标是**把问题稳稳当当解决**，不是产出最长的推理链。

但最大挑战是 **reward hacking**。模型有了工具后作弊空间急剧增大：
- 有搜索能力的模型可能训练时直接查答案
- 编程 Agent 可能利用不该看到的信息走捷径
- 环境漏洞可能让策略「看起来超强但其实在作弊」

**下一个卡脖子的研究瓶颈：环境设计、评估器鲁棒性、反作弊协议。**

未来的竞争优势来源也变了：推理时代拼 RL 算法和训练流水线，**智能体时代拼环境质量、harness 工程能力，以及能不能把决策和后果串成闭环。**

## 对 Builder 的启示

1. **别再只关注模型本身。** 环境、工具链、编排框架的质量正在成为核心竞争力。如果你在做 Agent 产品，环境设计应该拿到跟模型选型同等的重视。

2. **多 Agent 编排是真正的未来。** 核心智能越来越取决于多个 Agent 怎么组织——编排者、领域专家、子任务执行者。这不是花哨的架构图，是实际的工程方向。

3. **Reward hacking 是你现在就该关心的问题。** 给 Agent 接工具后，评估结果变得不可信的速度比你想象的快。环境隔离、反作弊、评估器鲁棒性——这些不是学术问题，是产品问题。

4. **「从训练模型到训练智能体，再到训练系统」。** 这条路径很清晰。如果你现在还在用静态 benchmark 选模型，可能已经在问错误的问题了。
